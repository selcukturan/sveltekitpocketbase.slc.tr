PocketBase listelerini SvelteKit remote functions ile gösteren, düzenleyen ve seçen, sanal kaydırmalı (satırları yeniden kullanan) bir veri tablosu. Excel'e yakın klavye ve fare davranışı (hücre gezinmesi, aralık seçimi, kopyala/yapıştır, hücre içi düzenleme), tek ya da çoklu satır seçimi, sağ tık menüsü, kolon ayarları, çoklu sıralama, filtreler ve footer hesapları içerir. Kolonlar ve sunucunun kabul ettiği izinler (sıralama, filtre, düzenleme) tek bir tablo tanımından (`defineTable`) türetilebilir.

## Hızlı başlangıç

En küçük kullanım: bir liste sorgusu ve kolonlar.

```svelte
<script lang="ts">
	import * as dt from '#lib/components/ui/datatable/index.js';
	import { listParamsSchema } from './page.shared';
	import { getList } from './page.remote';

	const list = dt.createList(getList, listParamsSchema); // filtre + sayfalama + sıralama + sorgu

	type Item = Awaited<ReturnType<typeof getList>>['items'][number];
	const columns: dt.Column<Item>[] = [
		{ field: 'id', label: 'dt_id' },
		{ field: 'text_required', label: 'dt_text_required' },
		{ field: 'number_optional', type: 'number' },
		{ field: 'updated', type: 'datetime' }
	];
</script>

<dt.DataTable {list} {columns} />
```

Bu kadarla şunlar çalışır: sayfalama, sıralama (Ctrl ile çoklu), sanal kaydırma, hücre gezinmesi, aralık seçimi, Ctrl+C, kolon genişletme/gizleme/sabitleme, kenarlık ve yoğunluk ayarları.

> [!TIP]
> Kolonları elle yazmak yerine `page.shared.ts`'te bir tablo tanımı (`defineTable`) kullanın: sıralama, filtre ve düzenleme izinleri sunucuyla aynı yerden gelir, liste şeması da tanımdan türer (`createList(getList, TABLE.listParamsSchema)`, `TABLE.columnsFor<Item>()`). Bkz. [Tablo tanımı](#tablo-tanımı-definetable).

Tam özellikli kullanım (Simple CRUD'dan, kısaltılmış; `columns = TABLE.columnsFor<Item>({ prepend: [seçim, işlem kolonları] })`, filtreler başlıkta `<dt.FilterBar {list} filters={TABLE.filters} />`):

```svelte
<dt.DataTable
	bind:this={table}
	{list}
	{columns}
	{footers}
	freezeLeft={2}
	selection="multiple"
	persist="grapes-crud-simple"
	{...cellEdit}
	onKeyDown={rowDelete.onKeyDown}
	onRowActivate={(row) => drawer.show('update', row.id)}
	onLoad={onTableLoad}
	onError={(error) => toaster.error(error)}
	onKeyDown={onTableKeyDown}
	rowClass={(row) => (row.bool_optional ? 'font-semibold' : undefined)}
>
	{#snippet actions(row)}
		<dt.ActionButton label={t('update')} icon="update" onclick={() => drawer.show('update', row.id)} />
		<dt.ActionButton label={t('delete')} icon="delete" onclick={() => remove(row.id)} />
	{/snippet}
	{#snippet contextMenu(row)}
		<dt.MenuItem label={t('update')} onclick={() => drawer.show('update', row.id)} />
		<dt.MenuItem label={t('delete')} danger onclick={() => remove(row.id)} />
	{/snippet}
</dt.DataTable>
```

## Mimari

Bileşenler sunumdan sorumludur. Durum ve davranış, `state/context.svelte.ts`'teki `TableContext` ile onun kullandığı küçük sınıflarda durur. Temel bileşenler kökte, destek dosyaları klasörlerde:

```
datatable/
  index.ts  DataTable.svelte  types.d.ts  Value.svelte
  HeaderRow / HeaderCell / DataRow / DataCell / FooterRow / FooterCell .svelte
  state/   durum sınıfları (.svelte.ts)
  utils/   saf yardımcılar (sunucuda da kullanılabilir)
  parts/   iç parçalar (alt bar, düzenleyici, işlem butonu)
```

| Dosya                                               | Görevi                                                                                                                                                 |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DataTable.svelte`                                  | Kök bileşen: context'i kurar, grid'i, alt barı ve iskeleti çizer; satır seçimini tutar (başlangıç `selected`, değişiklik `table.helpers`).             |
| `HeaderCell` / `DataCell` / `FooterCell` (+ `…Row`) | Hücre bileşenleri; kendi satır snippet'inizde kullanılabilir.                                                                                          |
| `Value.svelte`                                      | Değeri kolon tipine göre gösterir (tarih/sayı dile göre, bool ✓, liste virgülle…).                                                                     |
| `state/context.svelte.ts`                           | `TableContext`: props, veri uzlaştırma, sanal kaydırma, kolon yerleşimi, freeze, olay dinleyicileri, kopyalama, özet.                                  |
| `state/navigation.svelte.ts`                        | `GridCursor`: aktif hücre, aralık(lar), klavye gezinmesi, görünür alana kaydırma.                                                                      |
| `state/selection.svelte.ts`                         | `RowSelection`: satır seçimi (`id` ile).                                                                                                               |
| `state/editing.svelte.ts`                           | `CellEditor`: hücre düzenleme, doğrulama, yapıştırma, "kaydediliyor" durumu.                                                                           |
| `state/list-state.svelte.ts`                        | `ListState` / `createList`: filtre, sayfalama, sıralama ve sorgu.                                                                                      |
| `utils/sort.ts`                                     | Sıralama metni: `parseSort`, `formatSort`, `nextSort`, `isValidSort` (saf; sunucuda da kullanılır).                                                    |
| `utils/footer.ts`                                   | Footer kısayolları: `parseAggregate`, `aggregate`, `formatAggregate`.                                                                                  |
| `utils/format.ts`                                   | Intl biçimlendirici önbelleği: `numberFormat`, `dateFormat` (her seçenek + dil için bir kez kurulur).                                                  |
| `utils/filter.ts`                                   | `defineFilters`: filtre tanımından doğrulama şeması, güvenli PocketBase filtresi ve FilterBar alanları.                                                |
| `utils/table.ts`                                    | `defineTable`: kolonlar ve izinler tek tanımda; liste/düzenleme şemaları, filtreler, `canEdit`, `columnsFor<Item>()`.                                  |
| `parts/CellInput.svelte`                            | Hücre düzenleyicisi (metin, sayı, tarih, liste).                                                                                                       |
| `parts/`                                            | Alt bar parçaları (sayfalama, sayfa başına, kolonlar, ayarlar), işlem butonu, sağ tık menüsü (`ContextMenu`, `MenuItem`), filtre çubuğu (`FilterBar`). |

Tasarım ilkeleri:

- **Tek dinleyici:** Tıklama, çift tıklama, tuş, yapıştırma ve sağ tık olaylarının hepsi grid'deki tek bir dinleyicide işlenir. Hücreler kaydırmada sürekli başka kayıtları gösterdiği için hücre başına dinleyici bağlanmaz. Hücrenin konumu `data-row` / `data-col` attribute'larından okunur.
- **Satır geri dönüşümü:** Sanal kaydırmada satırlar kayıt `id`'si ile değil pencere içindeki yuvayla anahtarlanır (`virtualData`, `key = sıra % pencere boyu`). Pencere hep aynı boyda olduğu için kaydırırken satır bileşenleri ve DOM düğümleri yeniden oluşturulmaz, yalnızca gösterdikleri kayıt (`dr`) değişir. Ölçüm: 1000 satırı baştan sona kaydırmak eskiden yaklaşık 35 bin düğüm oluşturuyordu, şimdi hiç oluşturmuyor. Aktif satır pencereden çıkınca kendi yuvasında sabitlenir, böylece düzenleyici ve odak yerinde kalır.
- **Kolon bilgisi kolon başına bir kez:** Freeze, ofset ve hizalama `columnLayout`'ta kolon başına bir kez hesaplanır; hücreler hazır değeri okur.
- **Odak grid'de:** Grid kapsayıcısı `tabindex=0`. Aktif hücre `aria-activedescendant` ile gösterilir; hücreler odak almaz.
- **Aktif hücre ve satır ucuz:** Hücreler imlecin `cursor.key` (`"satır:kolon"`) ve `cursor.activeRow` değerlerini kendi konumlarıyla karşılaştırır (`data-active`, `data-active-row`). İmleç taşınınca yalnızca eski ve yeni hücrenin/satırın DOM'u değişir.
- **Callback ve `bind:` ayrımı:** Bir şey olduğunda bildirilenler callback prop (`onX(payload)`), sayfanın okuyup değiştirebileceği durum tablonun kendisinde. `bind:` kullanılmaz (`bind:this` hariç; helper'lara erişim için): başlangıç değeri prop olarak verilir (`selected`), değişiklik `table.helpers` ile yapılır, izleme callback'le (`onSelectionChange`, `onRangeChange`). Böylece aynı durumun iki sahibi olmaz ve effect içinde prop'a state kopyalamak gerekmez (Svelte: _When not to use `$effect`_).

## ListState (`createList`)

Liste sayfasının tek kontrol noktasıdır: filtre, sayfalama, sıralama ve sorgu burada tutulur. DataTable'ın tek veri kaynağıdır (`list={list}`, zorunlu): sorgu, sıralama (`setSort`) ve sayfalama (`paginate`) buradan okunur. Sorgu `ListResult` (sayfalı) ya da dizi (sayfalamasız) döndürebilir.

```ts
const list = dt.createList(getList, listParamsSchema, { autoLoad: true });
```

| Üye                                            | Açıklama                                                                                                                            |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `filter`                                       | Inputların bağlandığı taslak filtre (`bind:value={list.filter.x}`). `search()` çağrılana kadar sorguya gitmez.                      |
| `params`                                       | Sorguya giden, uygulanmış parametreler.                                                                                             |
| `query`                                        | Remote sorgu. `autoLoad: false` ise ilk `search()` / `refresh()` çağrısına kadar `undefined`.                                       |
| `sort`, `loading`, `loaded`                    | Okuma için.                                                                                                                         |
| `search()`, `searchOnEnter(e)`, `clear()`      | Filtreyi uygular ve 1. sayfaya döner; Enter ile arar; filtreyi sıfırlar.                                                            |
| `refresh()`                                    | Aynı parametrelerle yeniden çeker.                                                                                                  |
| `paginate({ page, perPage })`, `setSort(sort)` | Sayfalama ve sıralama. **İstek sürerken çağrılırsa yok sayılır** (art arda tıklamalar ayrı istek atmasın).                          |
| `updates`                                      | Mutasyonlarda tazelenecek sorgular: `submit().updates(...list.updates)`.                                                            |
| `updatesWith(fn)`                              | **Optimistik güncelleme** (SvelteKit `withOverride`): istek sürerken liste `fn` ile değiştirilmiş görünür, hata olursa geri alınır. |

```ts
// Optimistik: yeni değer sunucu yanıtından önce görünür (hücre düzenlemede bunu dt.createCellEdit yapar)
await updateCells([args]).updates(
	...list.updatesWith((result) => ({
		...result,
		items: result.items.map((item) => (item.id === args.id ? { ...item, [args.field]: args.value } : item))
	}))
);
```

> [!NOTE]
> Her `search` / `paginate` / `setSort` yeni bir sorgu örneği üretir (parametrelerde `timestamp` vardır). `refresh()` ve `.updates()` ise aynı örneği tazeler. Tablo yeni sorgunun verisi gelince en üste kayar; tazelemede konumu korur.

## Tablo tanımı (`defineTable`)

Kolonlar ve kolon başına izinler `page.shared.ts`'te **tek tanımda** durur. Sunucunun kabul ettiği sıralama alanları, filtreler ve hücre düzenlemeleri yalnızca buradaki işaretlerden türer; istemci ile sunucu birbirinden kopamaz.

```ts
// page.shared.ts (utils/table.js doğrudan içe aktarılır: sunucuda da çalışır)
import { defineTable } from '#lib/components/ui/datatable/utils/table.js';

export const TABLE = defineTable({
	defaultSort: 'text_required', // sortable alanlardan; '-alan' azalan, çoklu: '-number_optional,text_required'
	columns: {
		id: { label: 'dt_id', sortable: true },
		text_required: { label: 'dt_text_required', sortable: true, filter: true, edit: v.pipe(v.string(), v.trim(), v.nonEmpty('Bu alan zorunludur.')) },
		number_optional: { label: 'dt_number_optional', type: 'number', width: '130px', sortable: true, filter: true, edit: true },
		select_optional_single: { options: Object.values(Options), filter: true, edit: true },
		bool_optional: { type: 'bool', filter: true, edit: true, editable: (row) => !row.locked }, // satır kuralı
		updated: { type: 'datetime', sortable: true }
	}
});
```

| Grup             | Ayarlar                                                                                             | Kim kullanır      |
| ---------------- | --------------------------------------------------------------------------------------------------- | ----------------- |
| Sunum            | `label`, `type`, `width`, `align`, `alignHeader`, `alignFooter`, `hidden`, `resizeable`, `options`  | istemci           |
| İzinler (opt-in) | `sortable`, `filter` (`true`: türü kolondan), `edit` (`true`: türe göre şema, ya da valibot şeması) | sunucu doğrular   |
| Satır kuralı     | `editable: (row) => boolean` (saf)                                                                  | istemci ve sunucu |

`filter: true` türü kolondan alır: `options` → seçim, `number` → aralık, `date` → tarih aralığı (takvim günü), `datetime` → tarih-saat aralığı (uygulama saat diliminde, `config.timezone`; bitiş dakikası dahil), `bool` → evet/hayır, diğerleri → içerir. `edit: true` düzenleyicinin verdiği değer tipine göre şema kullanır (metin: kırpılmış string, sayı: `number | null`, bool, tarih: `'YYYY-MM-DD' | null`, `options`: listeden biri ya da `null`).

**`defaultSort`** PocketBase biçimindedir: `'-'` azalan, virgülle çoklu, ilk alan öncelikli (`'-updated'`, `'-number_optional,text_required'`, `''` = PocketBase varsayılanı). **Derleme zamanında denetlenir:** tanımda olmayan ya da `sortable: true` olmayan alan, tekrar eden alan editörde hata verir (örn. `"Geçersiz defaultSort: 'nam' tanımda yok ya da sortable: true değil"`). Parçalar arasında boşluk yazılmaz (`'-a,b'`). Aynı denetim çalışma zamanında da yapılır (modül yüklenirken hata).

**Türetilenler:**

| Üye                                             | Nerede                          | Açıklama                                                                                                                                                                     |
| ----------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TABLE.listParamsSchema`                        | `query(...)`, `createList(...)` | Yalnızca `page`, `perPage` (≤ 1000), doğrulanmış `options.sort` (varsayılanıyla) ve `filterData`. `expand` / `fields` istemciden gelmez, gerekiyorsa sunucuda sabit verilir. |
| `TABLE.filters`                                 | `toPb`, `FilterBar`             | `defineFilters` çıktısı (etiketler kolonlardan).                                                                                                                             |
| `TABLE.cellEditSchema` / `cellsEditSchema`      | `command(...)`, `validateCell`  | Yalnızca `edit` verilen alanlar düzenlenebilir.                                                                                                                              |
| `TABLE.canEdit(row, field)`, `TABLE.ruleFields` | sunucu                          | Satır kuralı olan alanlarda kaydın güncel hâli okunup denetlenir (Simple CRUD: `assertEditable`, 403).                                                                       |
| `TABLE.columnsFor<Item>(opts)`                  | sayfa                           | DataTable kolonları (aşağıda).                                                                                                                                               |

### Sayfada kolonlar: `columnsFor<Item>()`

Tanım satır tipini bilmez (alan adları string); veri kaynağı koleksiyon, view ya da özel sorgu olabilir. `Item` her zaman listenin döndürdüğü tiptir ve kontrol sayfada yapılır:

```ts
type Item = Awaited<ReturnType<typeof getList>>['items'][number];
const columns = TABLE.columnsFor<Item>({
	prepend: [
		{ field: '_select', type: 'select' },
		{ field: '_actions', type: 'actions', label: 'dt_actions' }
	],
	override: { id: { width: '80px' }, bool_optional: { editable: (row) => row.owner === me } },
	append: [{ field: '_total', label: 'Toplam', type: 'number' }],
	order: ['_select', 'id'] // isteğe bağlı; listede olmayanlar mevcut sıralarıyla sona
});
```

**Kural: sayfa sunumu değiştirebilir, izin veremez.**

- Tanımdaki bir alan `Item`'da yoksa **derleme hatası** (yazım hatası ya da view'ın döndürmediği alan).
- `override` yalnızca sunumu ezer; `sortable` / `filter` / `edit` verilemez (tip hatası). `editable` yalnızca **daraltılır**: `false` ya da tanımdaki kuralla VE'lenen ek kural.
- `prepend` / `append` kolonları istemcide yaşar: sıralanmaz, filtrelenmez, düzenlenmez (tip seviyesinde engellenir).

> [!IMPORTANT]
> Bir kolona `sortable` / `filter` / `edit` eklemek **sunucuda yeni bir izin açar**. Satır kuralı (`editable`) saf olmalı (sunucuda da çalışır); `t()`, snippet ya da bileşen tanımda kullanılamaz, etiketler çeviri anahtarıdır.

## Filtreler (`defineFilters`, `FilterBar`)

Filtrelenebilecek alanlar `page.shared.ts`'te **bir kez** tanımlanır. Aynı tanımdan üç şey üretilir: sunucunun doğruladığı şema, güvenli PocketBase filtresi ve filtre arayüzü. `defineTable` kullanılıyorsa filtreler kolonlardaki `filter` işaretinden gelir (`TABLE.filters`, etiketler kolonlardan):

```ts
const filter = TABLE.filters.toPb(locals.pb, params.filterData); // page.remote.ts
```

```svelte
<dt.FilterBar {list} filters={TABLE.filters} />
```

Tablo tanımı olmadan tek başına da kullanılabilir:

```ts
// page.shared.ts (utils/filter.js doğrudan içe aktarılır: sunucuda da çalışır)
import { defineFilters } from '#lib/components/ui/datatable/utils/filter.js';

export const FILTERS = defineFilters({
	text_required: 'text', // içerir (~)
	number_optional: 'number', // en az / en çok
	date_optional: 'date', // başlangıç / bitiş (gün dahil)
	bool_optional: 'bool', // Tümü / Evet / Hayır
	select_optional_single: { type: 'select', options: Object.values(Options) } // eşittir
});
export const listParamsSchema = v.object({ …, filterData: FILTERS.schema });
```

```ts
// page.remote.ts
const filter = FILTERS.toPb(locals.pb, params.filterData); // filtre yoksa ''
```

```svelte
<!-- +page.svelte: etiketler kolonlardan gelir -->
<dt.FilterBar {list} filters={FILTERS} {columns} />
```

- **Arayüz:** Metin filtreleri satır içinde (hızlı arama, Enter arar). Sayı, tarih, evet/hayır ve seçim filtreleri "Filtreler" panelinde; butonda uygulanmış filtre sayısı görünür. Ara uygular, Temizle tüm filtreleri (metin dahil) sıfırlayıp arar.
- **Değerler** hep metindir, `''` filtre yok demektir. `list.filter` anahtarları: metin/evet-hayır/seçim için alan adı, sayı ve tarih için `alan__min` / `alan__max`.
- **Filtreler birlikte uygulanır** (VE).

> [!IMPORTANT]
> **Güvenlik:** Filtre alanları ve operatörleri tanımla sınırlıdır (sıralamadaki `sortable` gibi). Sunucu değerleri `FILTERS.schema` ile doğrular (tanımda olmayan anahtarlar atılır, geçersiz sayı/tarih reddedilir). `toPb` alan adlarını yalnızca tanımdan alır, değerleri yer tutuculara (`{:f0}`) koyar. İstemci ham filtre metni gönderemez; liste şemasında serbest bir `filter` alanı bulunmamalı.

## Kolonlar

```ts
type Column<TData> = {
	field: Field<TData>; // veri alanı ya da '_' ile başlayan sanal alan ('_actions', '_select')
	label?: string; // çeviri anahtarı olabilir; bulunamazsa olduğu gibi gösterilir
	type?: 'text' | 'number' | 'bool' | 'date' | 'datetime' | 'list' | 'json' | 'actions' | 'select';
	hidden?: boolean;
	resizeable?: boolean; // varsayılan true
	sortable?: boolean; // elle yazılan kolonda varsayılan true; defineTable'da opt-in (varsayılan false). actions/select sıralanmaz
	align?: 'left' | 'center' | 'right';
	alignHeader?: Align;
	alignFooter?: Align;
	width?: Width; // '120px' | 'minmax(50px,1fr)' | 'minmax(1fr,2fr)'
	editable?: boolean | ((row: TData) => boolean);
	options?: readonly (string | { value: string; label: string })[]; // düzenlemede açılır liste
};
```

**Tip verilmezse** değerden tahmin edilir (`Value.svelte`): boolean → bool, number → number, dizi → list, nesne → json, `YYYY-MM-DD` → date, PocketBase tarih-saati → datetime. Kesin sonuç için `type` verin; örneğin `'5'` gibi bir metin `text` sayılır.

**Varsayılan genişlik** (`width` verilmezse, `dt.DEFAULT_COLUMN_WIDTHS`):

| Tip      | Genişlik               |
| -------- | ---------------------- |
| text     | `minmax(120px,1fr)`    |
| number   | `minmax(90px,0.75fr)`  |
| bool     | `minmax(70px,0.5fr)`   |
| date     | `minmax(110px,0.75fr)` |
| datetime | `minmax(160px,1fr)`    |
| list     | `minmax(140px,1fr)`    |
| json     | `minmax(160px,1.25fr)` |
| actions  | `minmax(100px,0.5fr)`  |
| select   | `44px`                 |

**Saat dilimi:** `datetime` gerçek andır (PocketBase'de UTC); uygulama saat diliminde (`config.timezone`) gösterilir, düzenlenir ve filtrelenir, tarayıcının saat dilimi kullanılmaz. Filtre paneli `inputs/` bileşenlerini kullanır (sayı: `Number nullable`, boş = filtre yok, 0 ≠ boş). `date` takvim günüdür (UTC gece yarısı) ve çevrilmeden gösterilir. Ayrıntı: `src/lib/utils/timezone.ts`.

**Varsayılan hizalama:** number / date / datetime sağda; bool / actions / select ortada; diğerleri solda. Başlık ve footer, verilmezse kolonun hizasını izler.

**Özel kolonlar:**

```ts
{ field: '_select', type: 'select' },                       // satır seçim onay kutuları (selection açıkken görünür)
{ field: '_actions', type: 'actions', label: 'dt_actions' }, // içerik: actions snippet'i
```

## Satır seçimi

```svelte
<script lang="ts">
	const columns: dt.Column<Item>[] = [{ field: '_select', type: 'select' } /* … */];
</script>

<!-- selected: başlangıç seçimi (isteğe bağlı). Değiştirmek: table.helpers; izlemek: onSelectionChange -->
<dt.DataTable bind:this={table} {list} {columns} selection="multiple" selected={['abc123']} onSelectionChange={(ids) => console.log(ids)} />
<button onclick={() => table?.helpers.clearSelection()}>Seçimi temizle</button>
```

- **Seçimin sahibi tablodur.** `selected` yalnızca başlangıç değeridir; sonradan değişmesi tabloyu etkilemez. Sayfa seçimi `table.helpers` ile okur ve değiştirir (`getSelected`, `setSelected`, `deselect`, `clearSelection`), değişiklikleri `onSelectionChange(ids)` ile izler (kullanıcıdan ya da helper'dan gelsin).

- **Aktif satır** (aktif hücrenin satırı) hafifçe renklenir (`--dt-row-active`): işlem yapılan satır gözle izlenir. Seçili satır ve hücre aralığı rengi bunun üzerindedir.
- Seçim kolonu `selection` kapalıyken görünmez ve "Kolonlar" menüsünde listelenmez.
- Alt barda "N seçili · Seçimi temizle" görünür.

## Hücre aralığı ve çoklu seçim

- **Tek aralık:** Shift ile (tuş, tıklama) ya da sürükleyerek seçilir. Aralık, sabit uç (anchor) ile aktif hücrenin dikdörtgenidir.
- **Çoklu seçim (Excel gibi):** Ctrl/⌘ + tıklama ya da sürükleme seçime yeni alan ekler. Shift son alanı genişletir. Seçili bir hücreye Ctrl+tıklama onu çıkarmaz, yalnızca aktif yapar.
- **Alt bar özeti:** "48 hücre · Toplam: 1.871,96 · Ort.: 233,99". Örtüşen hücreler bir kez sayılır; toplam ve ortalama yalnızca sayılardan hesaplanır. Sığmazsa `…` ile kısalır; tam metin `title`'dadır. Bar yüksekliğini değiştirmez.
- **Sayfadan okuma:** `onRangeChange(info)` → `{ ranges: CellRange[], count, numericCount, sum, average }` ya da seçim yoksa `undefined`.

```svelte
<script lang="ts">
	let range = $state<dt.RangeInfo>();
</script>

<dt.DataTable {list} {columns} onRangeChange={(info) => (range = info)} />
{#if range?.numericCount}<p>Seçilenlerin toplamı: {range.sum}</p>{/if}
```

## Kopyalama ve yapıştırma

**Ctrl/⌘+C** seçimi (yoksa aktif hücreyi) sekmeyle ayrılmış metin (TSV) olarak kopyalar; Excel ve Google Sheets'e yapıştırılabilir.

**Kopyalandı bildirimi:** Tablo, kopyalamadan sonra kendi sağ üst köşesinde küçük bir bilgi kutusu gösterir ("Kopyalandı · N hücre panoya kopyalandı."). Kutu yukarıdan kayarak gelir, 2,5 saniye sonra gider (kısmi kopyada uyarı renginde, 5 saniye). `role="status"` olduğu için ekran okuyucu da okur. Sayfanın toast yazması gerekmez.

- Seçim ve işlem kolonları atlanır. Değerler ham hâliyle kopyalanır: liste virgülle birleşir, nesne JSON olur, hücre içi sekme ve satır sonu boşluk olur.
- **Çoklu seçim:**
  - Alanlar aynı kolonlardaysa satırlar alt alta, aynı satırlardaysa kolonlar yan yana birleşir.
  - Değilse yalnızca son alan kopyalanır; bildirim uyarı renginde gösterilir ve `onCopy` `partial: true` ile çağrılır.

**Ctrl/⌘+V**, tarayıcının `paste` olayıyla çalışır; pano izni gerekmez.

- TSV okunur; Excel'in tırnaklı hücreleri de çözülür.
- **Tek değer + birden çok hücre ya da çoklu seçim:** Tüm alanlar doldurulur.
- **Blok:** Son alanın sol üstünden yazılır; yazılan alan seçili olur.
- **Atlananlar:** Düzenlenemeyen hücreler sessizce atlanır. Geçersiz değerler kaydedilmez ve `invalid` olarak sayılır.
- **Bool:** `evet / hayır / true / false / 1 / 0 / ✓` kabul edilir.
- **Kayıt:** `onCellsEdit` ile tek istekte yapılır (bkz. [Hücre düzenleme](#hücre-düzenleme)).

## Hücre düzenleme

### Tablo tarafı

```ts
const columns: dt.Column<Item>[] = [
	{ field: 'text_required', editable: true },
	{ field: 'number_optional', type: 'number', editable: true },
	{ field: 'select_optional_single', editable: true, options: Object.values(DemoCrudSelectOptionalSingleOptions) },
	{ field: 'date_optional', type: 'date', editable: true },
	{ field: 'bool_optional', type: 'bool', editable: true },
	{ field: 'text_optional', editable: (row) => !row.locked } // satır bazında
];
```

| Kolon tipi         | Düzenleyici                                                                 | `onCellEdit`'teki `value` |
| ------------------ | --------------------------------------------------------------------------- | ------------------------- |
| text               | Metin                                                                       | `string`                  |
| number             | Metin + sayısal klavye; dile göre ondalık (`747,44`), virgül ve nokta kabul | `number \| null`          |
| date               | Tarih seçici                                                                | `'YYYY-MM-DD' \| null`    |
| datetime           | Tarih-saat seçici (uygulama saat dilimi, `config.timezone`)                 | ISO `string \| null`      |
| `options` verilmiş | Açılır liste                                                                | `string \| null`          |
| bool               | Düzenleyici yok: F2 / Enter / çift tıklama değeri tersine çevirir           | `boolean`                 |

**Düzenlenebilirliğin önceliği:** `<DataCell editable>` → kolondaki fonksiyon ya da boolean → hiçbiri yoksa düzenlenemez. Ayrıca `onCellEdit` verilmemişse hiçbir hücre düzenlenmez.

### Sayfa tarafı (önerilen kalıp)

Düzenlenebilir alanlar ve doğrulamaları tablo tanımındadır (`edit`, satır kuralı `editable`); istemci ve sunucu aynı şemayı kullanır (bkz. [Tablo tanımı](#tablo-tanımı-definetable)).

```ts
// page.remote.ts — tek komut: tek hücre de bir elemanlı liste olarak gelir
export const updateCells = command(TABLE.cellsEditSchema, async (edits) => {
	await checkAuthenticated();
	await assertEditable(edits); // satır kuralı olan alanlarda: kaydı oku, TABLE.canEdit, değilse 403
	// kayıt bazında birleştir, her kayıt tek istek: update(id, { [field]: value ?? '' })
	await requested(getList, 1).refreshAll();
});
```

```ts
// +page.svelte — doğrulama, anında gösterme, kaydetme ve hata bildirimi tek yardımcıda
const cellEdit = dt.createCellEdit({ list, table: TABLE, save: updateCells, onError: toaster.error });
```

```svelte
<dt.DataTable {list} {columns} {...cellEdit} />
```

`dt.createCellEdit` DataTable'a üç özellik verir:

| Özellik        | Ne yapar                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `validateCell` | Kayıttan önce `TABLE.cellEditSchema` ile doğrular; mesaj dönerse düzenleyici açık kalır, mesaj hücrenin altında görünür.        |
| `onCellEdit`   | Tek hücreyi `save([düzenleme])` ile kaydeder; yeni değer `list.updatesWith` ile hemen görünür, hata olursa SvelteKit geri alır. |
| `onCellsEdit`  | Yapıştırma: tek istek. Geçersiz hücre sayısı `onError(null, 'N hücre yapıştırılamadı')` ile bildirilir.                         |

Kayıt hatası `onError(error)` ile bildirilir (`toaster.error` bu imzaya uyar).

> [!IMPORTANT]
> **Neden `form` değil `command`?** Hücre düzenleme, sayfadan bağımsız tablonun içinden, kodla ve tipli bir değerle (sayı, boolean, null) yapılır. Form fonksiyonları ise bir `<form>` elemanı ve FormData'dan okunan metin değerleri gerektirir. Kural: tek hücre için `command` + `withOverride`, çok alanlı düzenleme için drawer'daki `form` + `preflight`.

**Davranış:**

- Kayıt sürerken hücre "kaydediliyor" görünür (soluk, italik).
- Yeni değeri hemen göstermek SvelteKit'in işidir (`withOverride`); tablo kendi bekleyen değerini tutmaz.
- Veri tazelenince seçili aralık korunur.

## Satır silme (`createRowDelete`)

Silmenin sayfaya özgü olmayan kısmı tek yardımcıda: onay sorusu, silme komutu, listeyi tazeleme, silinenleri seçimden çıkarma (`table.helpers.deselect`) ve bildirim. Seçimi tablodan okuduğu için tabloyu (`bind:this`) alır.

```ts
// page.remote.ts — tek komut: tek kayıt da bir elemanlı liste olarak gelir
export const deleteRecords = command(deleteManySchema, async ({ ids }) => {
	await checkAuthenticated();
	// her id için collection.delete(id); hata varsa throwError
	await requested(getList, 1).refreshAll();
});
```

```ts
// +page.svelte
let table = $state<ReturnType<typeof dt.DataTable<Item>>>();
const rowDelete = dt.createRowDelete({ list, table: () => table, remove: deleteRecords, onSuccess: toaster.success, onError: toaster.error });
```

```svelte
<dt.DataTable bind:this={table} {list} {columns} onKeyDown={rowDelete.onKeyDown}>
	{#snippet contextMenu(row)}
		{@const targets = rowDelete.targetsOf(row.id)}
		<dt.MenuItem label={t('delete')} danger onclick={() => rowDelete.remove(targets)} />
	{/snippet}
	{#snippet actions(row)}
		<dt.ActionButton label={t('delete')} icon="delete" onclick={() => rowDelete.remove([row.id])} />
	{/snippet}
</dt.DataTable>
```

| Üye             | Ne yapar                                                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `remove(ids)`   | Onay sorar (tek kayıtta id ile, çokta sayıyla), onaylanırsa siler; başarıda `onSuccess(başlık, açıklama)`, hatada `onError(error)`. |
| `targetsOf(id)` | Sağ tık hedefleri: satır seçimdeyse tüm seçim, değilse yalnızca o satır.                                                            |
| `onKeyDown`     | Delete tuşu: seçili satırlar, seçim yoksa aktif hücrenin satırı. `preventDefault` yalnızca işlenince çağrılır.                      |

> [!NOTE]
> `{...rowDelete}` ile yayılmaz: `remove` ve `targetsOf` DataTable özelliği değildir, tanınmayan özellik olarak HTML'e düşerdi. `onKeyDown` açıkça bağlanır. Sayfa başka tuşlar da işleyecekse kendi `onKeyDown`'ını yazıp içinde `rowDelete.onKeyDown(e, ctx)` çağırır.

## Sıralama

- **Biçim (PocketBase):** Alanlar virgülle ayrılır, `-` azalan demektir, ilk alan önceliklidir: `-number_optional,text_required`. Sunucuda ek bir şey gerekmez; metin `getList`'e olduğu gibi gider.
- **Arayüz:**
  - Düz tıklama yalnızca o kolona göre sıralar.
  - Ctrl/⌘ + tıklama, kolonu çoklu sıralamaya ekler, azalana çevirir ya da çıkarır.
  - Birden çok kolon sıralanıyorsa okun yanında öncelik numarası (↓¹ ↑²) ve `title`'da "2. sıralama, artan" görünür.
  - `aria-sort` yalnızca birincil kolondadır.
- **Yardımcılar:** `dt.parseSort`, `dt.formatSort`, `dt.nextSort`, `dt.isValidSort`.

> [!WARNING]
> **Sunucuda sıralama alanlarını doğrulayın.** Serbest metin bir `sort`, gösterilmeyen bir alana göre sıralayarak o alan hakkında dolaylı bilgi sızdırabilir. `defineTable` kullanılıyorsa yalnızca `sortable: true` kolonlar kabul edilir (`TABLE.listParamsSchema`, varsayılan `defaultSort`). Tanım olmadan:
>
> ```ts
> sort: v.optional(v.pipe(v.string(), v.check((s) => isValidSort(s, SORTABLE), 'Geçersiz sıralama alanı.')), 'text_required'),
> ```
>
> `sort.ts`'i `index.ts` üzerinden değil doğrudan içe aktarın (`#lib/components/ui/datatable/utils/sort.js`): sunucu tarafına Svelte bileşenleri taşınmasın.

| Değer                                  | Sonuç                                                                                        |
| -------------------------------------- | -------------------------------------------------------------------------------------------- |
| `sum(n)`, `avg(n)`, `min(n)`, `max(n)` | `n` verilirse tam `n` basamak (`30,50`); `n` yoksa en fazla 2, sondaki sıfırlar yok (`20,5`) |
| `count()`                              | Boş olmayan değerlerin sayısı                                                                |
| `(items) => değer`                     | Fonksiyon; sonuç sayıysa aynı kurala göre biçimlenir                                         |
| Diğer her şey                          | Olduğu gibi metin                                                                            |

- Hesaplamalar yalnızca **yüklü satırlardan, yani bu sayfadan** yapılır. Hesaplanan hücrenin `title`'ı: "Bu sayfadaki N kayıttan hesaplandı".
- Boş ve sayı olmayan değerler atlanır; `avg` yalnızca sayıların ortalamasını alır. Hiç sayı yoksa hücre boş kalır.
- Veri değişince (düzenleme, yapıştırma, optimistik güncelleme) kendiliğinden güncellenir.
- Geliştirme modunda `summ(2)` gibi kısayola benzeyip uymayan değerler için konsolda bir kez uyarı çıkar.

> [!TIP]
> **Tüm kayıtların toplamı** gerekiyorsa sunucuda hesaplayıp footer'a düz değer olarak verin; kalıba uymayan değer metin olarak gösterilir.

## Görünüm ve kullanıcı ayarları

- **Alt bardaki ayarlar düğmesi:** Kenarlık (yok / yatay / dikey / ikisi), yoğunluk (sık / normal / rahat), sol ve sağ sabit kolon sayısı, "Varsayılana dön".
- **"Kolonlar" menüsü:** Kolon gizleme ve gösterme.
- **Genişletme:**
  - Tutamak başlığın üzerine gelince görünür.
  - Sürükleme karede bir kez uygulanır; sürüklerken yalnızca grid şablonu değişir, bırakınca kaydedilir.
  - İlk harekette diğer `minmax` kolonlar o anki genişliklerinde px'e sabitlenir; kaymasınlar diye.
- **`persist="anahtar"`:** Genişlik, gizleme, freeze, kenarlık ve yoğunluk `localStorage`'da `slc-dt:anahtar` adıyla saklanır. "Varsayılana dön" kaydı siler. Gizli pencerede ya da depolama engelliyken ayarlar yalnızca o oturumda kalır.
- **Sabit kolonlar:** Ofsetler başlık hücrelerinin gerçek genişliğinden ölçülür (`ResizeObserver`); `minmax` kolonlarda da doğrudur.
- **İlk yükleme:** Veri gelene kadar alt bar iskelet gösterir; kontroller birlikte gelir, bar yüksekliği değişmez.

## Render'ın tam kontrolü (snippet'ler)

Varsayılan satırlar çoğu ihtiyaç için yeterlidir. Hücreye özel içerik, koşullu görünüm ya da hücre bazında ayar gerekirse başlık, veri ve footer satırlarını kendiniz çizebilirsiniz. **Davranışlar korunur:** gezinme, seçim, aralık, düzenleme, freeze, genişletme ve sıralama hücre bileşenlerinde ve context'te durur. Siz yalnızca ne gösterileceğine karar verirsiniz.

### Yapı

Her satır snippet'i aynı kalıbı izler: satır bileşeni, içinde hücre snippet'i, içinde hücre bileşeni.

| Satır snippet'i (DataTable prop'u) | Satır bileşeni        | Hücre snippet'i  | Hücre bileşeni              |
| ---------------------------------- | --------------------- | ---------------- | --------------------------- |
| `headerRow(hr)`                    | `<dt.HeaderRow {hr}>` | `headerCell(hc)` | `<dt.HeaderCell {hr} {hc}>` |
| `dataRow(dr)`                      | `<dt.DataRow {dr}>`   | `dataCell(dc)`   | `<dt.DataCell {dr} {dc}>`   |
| `footerRow(fr)`                    | `<dt.FooterRow {fr}>` | `footerCell(fc)` | `<dt.FooterCell {fr} {fc}>` |

Snippet'lerin aldığı değerler (tipler `types.d.ts`'te):

| Değer | Alanlar                                                                                                |
| ----- | ------------------------------------------------------------------------------------------------------ |
| `hr`  | `headerIndex`                                                                                          |
| `hc`  | `label`, `col` (`{ data: Column, originalIndex }`), `colVisibleIndex`                                  |
| `dr`  | `row` (kayıt), `rowOriginalIndex` (yüklü verideki sıra), `rowVirtualIndex`                             |
| `dc`  | `value` (ham değer), `col`, `colVisibleIndex`                                                          |
| `fr`  | `footerRow` (footer tanımı), `footerIndex`                                                             |
| `fc`  | `value` (footer tanımındaki ham değer: kısayol metni, fonksiyon ya da metin), `col`, `colVisibleIndex` |

**Hücre bileşenlerinin ortak kuralları:**

- **`children` verilirse varsayılan içeriğin yerine geçer.**
  - `HeaderCell`'de etiketin yerine geçer; sıralama oku ve genişletme tutamağı kalır.
  - `DataCell`'de `<Value>`'nun yerine geçer.
  - `FooterCell`'de hesaplanan metnin yerine geçer.
- **`class`, `style` ve diğer HTML attribute'ları** hücreye aktarılır. `class`, `rowClass` ile birleşir.
- **Hücre kendi konumunu ve davranışını yönetir:** grid konumu, freeze, `data-row`/`data-col`, aktif ve seçili hâli. Yalnızca içeriği değiştirin, hücreyi başka bir elemanla sarmayın.

### Tam örnek

```svelte
<dt.DataTable {list} {columns} {footers} {...cellEdit}>
	<!-- Başlık: bir kolona birim ekle, diğerleri varsayılan -->
	{#snippet headerRow(hr)}
		<dt.HeaderRow {hr}>
			{#snippet headerCell(hc)}
				{#if hc.col.data.field === 'number_optional'}
					{@const label = hc.label ?? 'number_optional'}
					<dt.HeaderCell {hr} {hc} title="Tutarlar TL">
						{t(label, undefined, label)} <small>(TL)</small>
					</dt.HeaderCell>
				{:else}
					<dt.HeaderCell {hr} {hc} />
				{/if}
			{/snippet}
		</dt.HeaderRow>
	{/snippet}

	<!-- Veri: işlem butonları, rozet, hücre bazında düzenlenebilirlik ve koşullu class -->
	{#snippet dataRow(dr)}
		<dt.DataRow {dr}>
			{#snippet dataCell(dc)}
				{#if dc.col.data.type === 'actions'}
					<dt.DataCell {dr} {dc}>
						<div class="flex h-full w-full items-center justify-center gap-1">
							<dt.ActionButton label={t('update')} icon="update" onclick={() => open(dr.row.id)} />
						</div>
					</dt.DataCell>
				{:else if dc.col.data.field === 'select_optional_single'}
					<dt.DataCell {dr} {dc}>
						<span class="badge">{dc.value ?? '—'}</span>
					</dt.DataCell>
				{:else if dc.col.data.field === 'text_optional'}
					<!-- kolonda editable: true; işaretli satırlarda bu hücre düzenlenemez -->
					<dt.DataCell {dr} {dc} editable={!dr.row.bool_optional} />
				{:else if dc.col.data.field === 'number_optional'}
					<!-- özel içerik + biçim korunsun diye Value; negatif sayı kırmızı -->
					<dt.DataCell {dr} {dc} class={Number(dc.value) < 0 ? 'text-error-600' : undefined}>
						<dt.Value value={dc.value} type="number" />
					</dt.DataCell>
				{:else}
					<dt.DataCell {dr} {dc} />
				{/if}
			{/snippet}
		</dt.DataRow>
	{/snippet}

	<!-- Footer: bir hücrede hesabı kendiniz gösterin, diğerleri varsayılan (kısayollar çalışır) -->
	{#snippet footerRow(fr)}
		<dt.FooterRow {fr}>
			{#snippet footerCell(fc)}
				{#if fc.col.data.field === 'number_optional' && fr.footerIndex === 0}
					{@const sum = dt.aggregate('sum', list.query?.current?.items ?? [], 'number_optional')}
					<dt.FooterCell {fr} {fc}>
						<strong>{sum === undefined ? '' : dt.formatAggregate(sum, 2, getSelectedLang())} ₺</strong>
					</dt.FooterCell>
				{:else}
					<dt.FooterCell {fr} {fc} />
				{/if}
			{/snippet}
		</dt.FooterRow>
	{/snippet}
</dt.DataTable>
```

> [!IMPORTANT]
> **`dataRow` verince `actions` snippet'i kendiliğinden çizilmez.** İşlem kolonunu varsayılan veri satırı çizer. Kendi satırınızda `type === 'actions'` kolonunu yukarıdaki gibi siz doldurun. Seçim kolonu (`type: 'select'`) ise `DataCell`'in kendisinde çizilir; `children` vermezseniz onay kutusu gelir.

### Hücre bazında düzenlenebilirlik (`editable`)

`<dt.DataCell editable={…}>` kolondaki `editable`'ı **yalnızca o hücre için** geçersiz kılar:

| Kolon                   | `DataCell editable` | Sonuç                                    |
| ----------------------- | ------------------- | ---------------------------------------- |
| `editable: true`        | verilmedi           | Düzenlenir                               |
| `editable: true`        | `false`             | **Düzenlenmez** (o hücre için kapatılır) |
| `editable: false` / yok | `true`              | **Düzenlenir** (o hücre için açılır)     |
| `editable: (row) => …`  | verilmedi           | Fonksiyonun sonucu                       |
| herhangi                | `true` / `false`    | `DataCell`'deki değer kazanır            |

Kurallar ve ayrıntılar:

- **Ön koşullar:** DataTable'a `onCellEdit` verilmiş olmalı ve kolon tipinin bir düzenleyicisi olmalı (text, number, bool, date, datetime ya da `options`). Liste, JSON, `actions` ve `select` kolonları `editable={true}` ile de düzenlenmez.
- **Hangi yolları etkiler:** Düzenlemenin her yolu bu kararı izler: F2, Enter, yazmaya başlamak, çift tıklama ve Ctrl+V. Yapıştırmada düzenlenemeyen hücreler sessizce atlanır.
- **Nasıl çalışır:** Değer, hücre DOM'dayken bir attachment ile tabloya bildirilir ve kaydın `id`'si ile alan adına göre tutulur. Hücre başka bir kaydı göstermeye başlayınca ya da DOM'dan kalkınca eski kayıt silinir. Aktif hücre her zaman DOM'da tutulduğu için klavyeyle düzenlemede sorun olmaz.
- **Basit durumda gerek yok:** Karar yalnızca satıra bağlıysa kolonda `editable: (row) => !row.locked` yeterlidir; kendi snippet'inizi yazmanız gerekmez. `DataCell editable`, render'ı zaten kendiniz yaptığınızda ya da karar satırın dışındaki bir şeye bağlı olduğunda kullanışlıdır (izinler, sayfa durumu…).
- **`children` ile birlikte:** Düzenleme sırasında düzenleyici görünür. Düzenleme bitince yeniden `children` görünür; `children`, düzenleyiciyi etkilemez.

### İpuçları

- **`DataCell` yalnızca `dr`, `dc`, `class`, `editable` ve `children` alır.** Ek HTML attribute'u (`title`, `onclick`, `data-*` …) verilemez: spread, kaydırmada her hücrenin tüm attribute'larını yeniden kurdurduğu için kaldırıldı. Böyle bir şey gerekiyorsa `children` içindeki kendi elemanınıza verin.
- **Biçimi korumak için `<dt.Value>` kullanın.** `<dt.Value value={dc.value} type="number" />` tarih, sayı ve bool biçimini tablonun geri kalanıyla aynı tutar.
- **Çeviri yedeği:** Başlıkta `t(label)` yerine `t(label, undefined, label)` kullanın. Çeviri yoksa "… not found" mesajı yerine etiket görünür.
- **Footer'da kısayolu koruyun:** Özel `FooterCell` yazmadığınız hücrelerde kısayollar (`sum(2)` …) çalışmaya devam eder. Kendi hesabınız için `dt.aggregate` ve `dt.formatAggregate` aynı kuralları uygular.
- **Durumu satırda tutmayın:** Satırlar kaydırmada yeniden kullanılır: aynı bileşen kaydırınca başka bir kaydı gösterir. Satır içinde tutulan `$state` kayıtla değil yuvayla kalır, yani yanlış kayda taşınır. Durumu sayfada `row.id` ile tutun; satırda yalnızca `dr`'den türetin (`$derived`).
- **Kendi satır elemanınızda `data-row-id`:** `<dt.DataRow>` kullanmıyorsanız satır kapsayıcısına `data-row-id={dr.row.id}` verin. Odak koruması bununla, odaklı butonun satırı başka kayda geçince odağı grid'e geri verir.
- **Koşullu görünüm için önce prop'lara bakın:** `rowClass(row)` ya da kolondaki `align`/`type` çoğu zaman yeterlidir; snippet'e yalnızca içerik değişecekse geçin.

### Diğer snippet'ler

- `toolbar`: Tablonun üstü.
- `statusbar`: Alt barın altı. Örnek: "Görünen satırlar: 1–12 / 30".
- `actions(row)`: `type: 'actions'` kolonunun içeriği (varsayılan veri satırında). `dt.ActionButton` tooltip'li ve `tabindex=-1`'dir.
- `contextMenu(row)`: Sağ tık menüsünün öğeleri (`dt.MenuItem`). Bkz. [Sağ tık menüsü](#tarifler-ve-ipuçları).

## Kritik bilgiler

> [!IMPORTANT]
> **Svelte async modu açık** (`vite.config.ts` → `experimental.async: true`). Remote sorgulardan gelen DOM güncellemeleri `tick()`'ten sonra uygulanabilir; attachment temizliği de DOM düğümü kaldırıldıktan sonra çalışır. "Bir eleman DOM'dan kalkınca bir şey yap" gerekiyorsa `MutationObserver` kullanın. Silinen satırla kaybolan odak bu yüzden `MutationObserver` ile grid'e geri verilir. Satırlar yeniden kullanıldığı için gözlemci ayrıca `data-row-id` değişimini de izler: silinen kaydın yuvasına sonraki kayıt geçtiğinde odak, başka kaydın Sil butonunda kalmaz.

> [!IMPORTANT]
> **SvelteKit 3:** `dev`, `browser` gibi bayraklar `$app/environment`'tan değil **`$app/env`**'den gelir.

> [!WARNING]
> **Sanal kaydırma ve satır yüksekliği:** Satırlar sabit yükseklikte çizilir (`dataRowHeight`); hücre içeriği taşarsa kesilir. Değişken yükseklikli satır ya da hücrede çok satırlı metin desteklenmez. Uzun metin `…` ile kısalır, tam hâli `title`'dadır.

> [!WARNING]
> **Footer hesapları ve aralık özeti yalnızca yüklü sayfayı kapsar.** Tüm kayıtlar için sunucuda hesaplayın.

- **Seçim `id` ile tutulur:** Satırların benzersiz bir `id`'si olmalıdır (`Row = { id: string | number }`).
- **`persist` anahtarı uygulamada tekil olmalıdır.** Aynı anahtarı kullanan iki tablo birbirinin ayarlarını ezer.
- **`freezeLeft` / `freezeRight` görünür kolonlara göre sayar.** Örneğin seçim kolonu `selection` kapalıyken görünmez; o zaman sayı bir kayar.
- **İstek sürerken sayfalama ve sıralama kilitlidir.** Hem arayüz devre dışıdır hem `ListState` çağrıyı yok sayar.
- **Toplu işlem sınırı:** Yapıştırma ve toplu silme şemaları bir istekte en fazla 1000 öğe kabul eder.
- **Kırıcı değişiklik (alpha.171):** `RangeInfo` artık `ranges: CellRange[]` içerir; `KeyContext.range` adı `ranges` oldu.
- **Kırıcı değişiklik (alpha.208):** `bind:range` kaldırıldı; aralık özeti `onRangeChange(info)` ile okunur.
- **Kırıcı değişiklik (alpha.209):** `bind:selected` ve `list.selected` kaldırıldı. `selected` yalnızca başlangıç seçimi; değişiklik `table.helpers` (`getSelected`, `setSelected`, `deselect`, `clearSelection`), izleme `onSelectionChange`. `createRowDelete` tabloyu alır: `{ list, table: () => table, … }`.

## Tarifler ve ipuçları

**Delete ile seçili satırları silmek** (`onKeyDown`): hazırı `rowDelete.onKeyDown` (bkz. [Satır silme](#satır-silme-createrowdelete)). Başka bir tuşla birlikte:

```ts
const onTableKeyDown = (e: KeyboardEvent, ctx: dt.KeyContext<Item>) => {
	if (e.key === 'F5') {
		e.preventDefault();
		list.refresh();
		return;
	}
	rowDelete.onKeyDown(e, ctx);
};
```

**Sağ tık menüsü** (`contextMenu` snippet'i + `dt.MenuItem`)

```svelte
<dt.DataTable …>
	{#snippet contextMenu(row)}
		<dt.MenuItem label={t('update')} onclick={() => drawer.show('update', row.id)} />
		<dt.MenuItem label={t('dt_copy')} onclick={() => table?.helpers.copy()} />
		<dt.MenuItem label={t('delete')} danger onclick={() => rowDelete.remove(rowDelete.targetsOf(row.id))} />
	{/snippet}
</dt.DataTable>
```

Menüyü tablo açar ve yönetir: imlecin olduğu yerde açılır (ekrana sığmazsa içeri kayar), ilk öğe odak alır, ↑ ↓ Home End gezinir. Esc, dışarı tıklama ya da tablo kaydırılınca kapanır ve odak tabloya döner. Klavyede ContextMenu tuşu ya da Shift+F10 menüyü aktif hücrenin üzerinde açar. `MenuItem` tıklanınca sırasıyla odağı tabloya verir, işlemi çalıştırır, menüyü kapatır (işlem bir onay penceresi açarsa odak kapanınca tabloya döner). Props: `label`, `onclick`, `danger`, `disabled`. Renkler tablonun `--dt-*` değişkenlerinden gelir.

**Boş arama sonucunda bilgi vermek** (`onLoad`)

```ts
const onTableLoad = ({ reason, totalItems }: dt.LoadEvent<Item>) => {
	if (reason === 'query' && totalItems === 0) toaster.add({ type: 'info', title: t('dt_no_data') });
};
```

**Görünen satırları göstermek** (`onVisibleRowsChange` + `statusbar`)

```svelte
<script lang="ts">
	let visibleRows = $state<dt.VisibleRows>();
</script>

<dt.DataTable onVisibleRowsChange={(rows) => (visibleRows = rows)} …>
	{#snippet statusbar()}
		{#if visibleRows && visibleRows.total > 0}
			<p>Görünen satırlar: {visibleRows.first + 1}–{visibleRows.last + 1} / {visibleRows.total}</p>
		{/if}
	{/snippet}
</dt.DataTable>
```

> [!NOTE]
> Tablo her seferinde **tek bir sayfayı** gösterir; `list.paginate` sonraki sayfayı eklemez, yerine koyar. Sonsuz kaydırma (sona yaklaşınca sonraki sayfayı **eklemek**) için sayfaların birikmesi gerekir ve bu bugün desteklenmiyor. `onVisibleRowsChange` bunun için gereken sinyali verir: `last`, `total`'e yaklaştığında.

**Koşullu satır görünümü** (`rowClass`)

```ts
rowClass={(row) => (isOverdue(row) ? 'text-error-600' : undefined)}
```

> [!TIP]
> `rowClass` hücreye class ekler. Arka plan rengi vermek isterseniz hover, seçili satır ve aralık renklerinin `!important` olduğunu unutmayın; metin rengi ya da yazı kalınlığı daha güvenlidir.

**Diğer ipuçları:**

- **Kolon bazında hizalama:** `align`, `alignHeader`, `alignFooter`. Sayısal ve tarih kolonları zaten sağa dayalıdır, başlık da onlarla aynı kenarda biter.
- **Çok kolonlu tablolarda:** Sol tarafta kimlik ya da ad kolonunu sabitleyin (`freezeLeft`), kullanıcıya "Kolonlar" menüsünü bırakın.
- **Bir alanı yalnızca bazı satırlarda düzenlenebilir yapmak:** `editable: (row) => …` yeterlidir; kendi `dataRow` snippet'inizi yazmanıza gerek yok.
